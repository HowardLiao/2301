01 · Strategic Paradigms

企業 AI 路由生態的四大架構原型

From Consumer Tiering to Sovereign Edge-Cloud Gateway

原型 1

消費端體驗路由

代表：ChatGPT (Fast vs Thinking)

面向終端對話體驗，由原廠黑盒動態配置模型。但缺乏 API 成本控制開關，企業無法控管每筆請求的財務上限與合規名單。

原型 2

公有雲閉環生態

代表：Google Vertex、AWS Bedrock、MS Foundry

在各自雲端 VPC 邊界內優化成本與調度。適合特許合規產業，但存在嚴重的單一廠商鎖定（Vendor Lock-in），無法跨巨頭調度。

原型 3

中立第三方代管閘道

代表：MixRoute、OpenRouter

中立聚合全球商業與開源模型，隨插即用、雙層比價、降本 20%~40%。但流量經由外部 Proxy，製造業核心機密難以通過嚴苛資安稽核。

原型 4 · 最佳實踐

企業專有主權混合閘道

代表：光寶 Howard Route

在地邊緣私有算力 (vLLM) + 內嵌 DLP 脫敏 + 跨雲旗艦升級。兼具數據絕對主權、工廠斷網容災與 70%+ TCO 實質降本。

Google Vertex AI Model Optimizer 三大路由模式機制

Google Vertex AI 提供 Model Routing（模型優化器）機制，不綁定單一模型，而是依提示複雜度與策略目標自動分流。官方提供三種核心調度模式：

1. Cost 經濟優先

偏向較便宜的模型

機制特徵：偏向選擇成本較低的模型（如 Gemini Flash / Flash-Lite），在複雜邏輯或超長思考任務中品質可能有所取捨。

適用場景：高並發客服意圖分類、文本欄位結構化抽取、固定 JSON 格式整理、低風險內部表單處理。
2. Balanced 平衡模式（預設）

平衡成本與品質

機制特徵：預設調度模式。在維持合理 Token 費用的前提下，動態兼顧推理深度、回應準確性與回應延遲（Latency）。

適用場景：標準業務問答、產品常見問答諮詢、工廠日誌營運摘要生成、標準作業程序（SOP）初稿撰寫。
3. Quality 品質優先

優先最高品質模型

機制特徵：優先選擇對該提示品質最高的模型（如 Gemini Pro / Thinking），不以成本為優先考量，全力確保邏輯嚴密。

適用場景：跨系統事故根因分析（RCA）、精密代碼安全漏洞排查、高階架構權衡決策、跨模態複合推理。
製造業限制警訊：Google Vertex AI 的這三種模式雖然靈活，但所有流量必須完全上傳至 GCP 雲端。對於光寶的 PSU 製程電壓曲線、專利 CAD 圖面與客戶客製化 BOM 表，即便選用 `Cost` 模式，依然面臨製造數據出廠與跨國海纜中斷停線的風險。

🔍 Google Vertex AI Model Optimizer 技術深入 ▼

路由演算法：採用 Google 內部訓練之輕量級分類器，依據輸入 Prompt 詞元結構、指令複雜度與語義熵進行評估。

三種調度策略：
• Cost：強制指派最具性價比之模型（如 Gemini 1.5 Flash、Flash-8B）。在超長長文本推論與深層多步驟思考時可能損失準確度。
• Balanced：標準生產環境建議值，兼顧 95% 回覆精準度與延遲。
• Quality：自動路由至 Gemini 1.5 Pro 或 Gemini 2.0 Thinking，無視成本，確保最高驗收通過率。

企業痛點：完全鎖定在 GCP 生態，無法將任務路由至 Azure GPT-4o 或 Anthropic Claude 3.7，亦無法原生結合地端 GPU 叢集。

🔍 MixRoute 智能代管閘道技術深入 ▼

路由架構：採用極速 In-Memory 路由器，在 5~15ms 內解析請求複雜度，並依據即時健康檢查將任務分發至全網 30+ 算力供應商。

安全宣告：提供 Zero Data Retention (ZDR) 承諾，即時轉發不落地。但對於製造業 ISO 27001、客戶 NDA 與國防級電源供應器（PSU）專利資料，外部中繼跳板依舊是資安長（CISO）的合規阻礙。

🔍 光寶 Howard Route 主權混合雲技術架構細節 ▼

核心設計思想：把 70% 內部高頻標準任務留在地端私有算力（vLLM + Qwen-2.5 / Llama-3.3），邊際 Token 成本為 0。

DLP 脫敏層：內嵌正則表達式（Regex）、光寶自建料號詞庫與 NER 實體辨識，於 Tier 2 閘道進行單向不可逆雜湊脫敏（如 LT-PSU-8500-REV3 ➔ [REDACTED_PART_A81F]），雲端供應商永遠無法重構原始商業機密。

跨雲動態容錯：支援 Azure OpenAI、AWS Bedrock 與 Google Vertex 三雲平行掛載，依實時 SLA 與價格策略自動 failover，確保零停機。

04 · Architecture Decision Flow

🌲 製造業任務路由互動決策樹

Three Questions to Determine the Optimal Routing Destination

問題 1：任務是否包含光寶未公開專利、客戶料號、客戶機密 BOM 或產線波形？
問題 2：產線是否要求極致低時延（< 50ms），或工廠處於實體隔離/海纜斷線環境？
問題 3：任務是否需要百萬 Token 超長上下文、高難度代碼重構或頂級 Thinking 推理？

💡 最佳架構推薦：【Tier 1 地端私有 SLM 叢集 (vLLM)】

判定理由：由於資料包含核心製程機密且要求極致低時延，嚴禁出雲。Howard Route 自動指派地端 GPU 叢集執行 Qwen-2.5 / Llama-3.3 推理，資料完全不經外網，確保 100% 主權合規且邊際成本為 0。

05 · Sovereign Pipeline Architecture

光寶 Howard Route 三層架構與安全邊界拓撲

The 3-Tier Edge-Gateway-Cloud Architecture with In-line DLP

01

私有端點優先消化

Tier 1: Local Edge SLM

所有工廠 MES 請求首先抵達內部閘道。70% 內部高頻標準任務（料號比對、規格快問、不良日誌初篩）直接由地端 vLLM (Qwen-2.5/Llama-3.3) 秒級回應，延遲 < 35ms，Token 費用為 0。

02

內嵌 DLP 脫敏清洗

Tier 2: In-line Sanitizer

若任務難度超出地端能力需升級雲端，資料強制經過 Tier 2 閘道脫敏引擎。自動遮蔽客戶料號、客戶代碼、專利敏感電路與製程數據，確保出廠資料僅具備抽象通用特徵。

03

動態跨雲負載平衡

Tier 3: Multi-Cloud Dispatch

僅 30% 脫敏後之超難任務發送至 Azure OpenAI (GPT-4o)、Anthropic (Claude 3.7) 或 Google Vertex。內建跨雲 Failover 機制，若任一公有雲當機或配額超限，0.3 秒無感切換。

04

本地向量快取與審計

Semantic Cache & Audit

所有雲端回應在返還業務端前，於地端建立語意向量快取（Semantic Cache）與完整加密審計日誌。相同或高度相似之技術詢問下次直接命中地端快取，進一步壓低雲端支出。
